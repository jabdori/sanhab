# 17: 보고

**What to build:** 정황에 AI의 보고가 붙고, 내부 감시가 그것을 보고 채택 또는 불채택을 남긴다. 사실은 기록을 가리키기만 하고 값은 코드가 채운다.

**Blocked by:** 11 정황

**Status:** ready-for-agent

- [ ] 서버가 OpenAI를 부르고 DB를 읽는 도구를 실행한다. 모델은 환경변수로 바꿀 수 있고 기본은 gpt-6.1-terra다. 연결 방식은 `docs/spike/`의 검증 코드를 따른다
- [ ] AI는 DB를 읽기만 한다. 쓸 수 있는 것은 보고뿐이고, 권한으로 강제된다
- [ ] 정황이 접수되면 보고가 만들어진다. 같은 입력에는 저장된 보고를 쓰고 다시 호출하지 않는다
- [ ] 보고는 사실 / 추정 / 미확인 / 의견 / 반론으로 이루어진다. 사실의 각 문장은 기록을 가리키고(선 21) 금액·이름·날짜는 코드가 그 기록에서 꺼내 보여 준다
- [ ] 없는 기록을 가리킨 보고는 오류가 되어 내부 감시에 올라가지 않는다
- [ ] 판단 칸의 보고: 머리에 AI와 상태. 사실 문장 끝의 연결을 누르면 가운데 근거 표의 해당 줄이 강조된다. 미확인은 펼쳐져 있고 의견은 접혀 있다. 확신을 숫자로 적지 않는다
- [ ] 가설에서 승인권자가 올라가는 정황에서는 내부 감시가 조치를 고른 뒤에야 의견이 열린다
- [ ] 내부 감시가 채택 또는 불채택을 남긴다(불채택은 사유 필수, 선 29). AI의 의견과 내부 감시의 조치가 같은지 다른지가 기록된다
- [ ] AI가 응답하지 않으면 보고는 대기로 남고 심사·지급·정황의 조치는 그대로 된다
- [ ] 가운데에는 AI가 쓴 글이 없다
- [ ] 이 티켓의 숫자와 상태 변화를 확인하는 자동 검사가 통과한다
- [ ] 별도 에이전트의 화면 검수(`docs/design/review.md`)에서 막힘과 어김이 없다
