# 04: 심사

**What to build:** 영업지원이 작업에서 6월 심사 하나를 열어 합산·한도·승인권자와 근거를 보고 승인한다. 정황 없는 건은 여러 개를 골라 한 번에 승인한다. (시나리오 1 앞부분)

**Blocked by:** 03 관련자

**Status:** done — `w07`에 합침. Codex 검토 3건(P2 둘, P3 하나) 수정, 화면 검수 2회차에서 남은 어김 1건(작업 목록의 금액 열)은 문서를 화면에 맞춤(`.scratch/w07/review/t04/r2/`)

- [x] 미지급인 6월 지급 40건에서 그룹별로 심사 38개가 만들어진다(그룹 1개에 3건, 나머지는 단독)
- [x] 합산은 귀속월 기준이고 반려만 뺀다. 한도는 규칙에서 읽는다(2,000,000). 합산이 한도 이하이면 승인권자는 영업지원, 넘으면 영업임원
- [x] 심사는 적용한 규칙 버전에, 규칙 버전은 조항과 문서에 이어진다(선 7, 8, 11). 규칙 버전은 시행 기간을 갖고 귀속월로 고른다
- [x] 작업은 담당과 진행으로 나뉘고, 역할마다 자기 것이 보인다
- [x] 심사 상세: 가운데에 제목 줄, 숫자 줄(`합산 988,932  한도 2,000,000  승인권자 영업지원`), 구성, 관계, 규정. 오른쪽에 조치 → 사유 → 보고 → 경위 → 이력(없는 칸은 `없음`)
- [x] 영업지원이 대성상사1의 심사를 승인하면 상태가 승인이 되고, 그때의 구성·합산·승인권자·규칙 버전이 굳는다. 결정은 사람과 시각과 함께 이력에 남는다
- [x] 승인 권한은 DB가 강제한다. 화면을 거치지 않은 요청도 권한이 없으면 거절된다
- [x] 정황이 없고 승인권자가 영업지원인 심사만 여러 개 골라 확인 창을 거쳐 한 번에 승인할 수 있다
- [x] 이 티켓의 숫자와 상태 변화를 확인하는 자동 검사가 통과한다
- [x] 별도 에이전트의 화면 검수(`docs/design/review.md`)에서 막힘과 어김이 없다
