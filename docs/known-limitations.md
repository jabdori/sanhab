# 알려진 한계

회계 전문가의 화면 시험(시나리오 18개, 2026-11-14)에서 나왔지만 이번 제출 범위에서 고치지 않은 것과 그 이유. 고친 것은 결정 기록(D63~D66)과 커밋에 있다.

| 한계 | 왜 지금 고치지 않나 | 대신 |
|---|---|---|
| 지급 금액 입력 · 귀속월 변경 기능이 없다(한도 경계값 2,000,000원, 같은 달 쪼개기 시험을 할 수 없다) | 지급은 원본 데이터(sales_rebate_payment_cv.csv)에서 오고, 이 앱은 원본을 바꾸지 않는다. 금액을 고치는 기능은 통제 대상 자체를 바꾸는 일이라 별도 설계가 필요하다 | 원본에서 가장 가까운 경계(한라인상사34 + 금강상사41의 3월 2,007,205원 → 100.4%, 영업임원)로 본다 |
| 재검토에서 "당시 알 수 있었던 정보"(원본에 이미 등록된 관계)와 "나중에 알게 된 변경"(소급 변경)을 한눈에 가르는 표시가 없다 | 변경의 변경일 · 인지일은 근거 표에 있지만 재검토 표에는 모으지 않았다 | 재검토의 경위 탭과 정황의 근거(변경일 · 인지일 · 지연)로 본다 |
| 노란색 하나가 정황 · 보류 · 재심사 · 보완을 뜻한다 | 색은 의미가 있을 때만(주의 · 오류 · 완료) 쓰는 규칙(tokens.md) — 종류는 아이콘과 낱말로 가른다 | 표지의 아이콘 · 낱말 |
| 이력에 시각 없이 날짜만, 처리자는 역할 이름뿐 | 시연은 역할 넷으로 접속한다(사람 계정 없음) | 대화는 실제 시각을 남긴다(D62) |
| 주소창 링크로 특정 기록을 열 수 없다 | 화면 이동을 앱 안의 상태로 한다 | 대화의 `@`로 기록을 찾아 연다 |
| 회계·자금이 완료된 지급을 작업 목록에서 다시 찾을 수 없다 | 작업 목록은 할 일만 보인다 | 대리점 화면의 지급 표에서 모든 지급과 그 심사를 연다 |
| 로컬 시험용 고정 응답의 AI 문장이 정황 종류와 상관없이 비슷하다 | 실제 배포본은 모델이 그 정황의 기록을 읽고 쓴다 | 배포본에서 실제 모델로 확인한다 |
| 은행 회신이 회계·자금 이름으로 기록된다 | 은행 연동이 없어 회계·자금이 모의 회신을 넣는다(출처 `모의`) | 출처 표지 `모의` |
| 작업 목록에서 반려된 심사가 따로 눈에 띄지 않고, 묶음 이름이 `재상신 · 심사`처럼 두 단계를 합친다 | 묶음은 종류 순서로 고정했다 | 심사 요약에 반려 사유 · 담당(영업지원)이 보인다 |
| 대리점 지급 표의 심사 이름이 1~5월은 그 대리점 단독, 6월은 그룹 이름으로 섞인다 | 과거 승인은 그때의 심사(단독)를, 6월은 지금 든 심사를 가리킨다 | 심사를 열면 구성이 보인다 |
| 회신이 실패한 건의 대사 비교 칸에 `실패`가 들어간다 | 실패한 회신은 대사를 남기지 않고 지급이 대기로 돌아간다(돈이 나가지 않음) | 지급 단추가 다시 생긴다 |
| 거부로 닫힌 추인은 영업임원의 전체 작업 목록에 남지 않는다 | 작업 목록은 할 일만 보인다 | 거부로 생긴 정황(`거부 · …`)이 내부 감시에 남는다 |
| 계좌 정황의 소명에 임대차계약서를 내면 판독 표가 호실 비교를 함께 보인다 | 판독은 서류마다 같은 항목(임차인 · 주소 · 호실 · 기간)을 정리한다 | 인정은 막히고 빠진 서류가 누락으로 보인다(D65) |
| 소명의 `누락` 수는 일치 종류마다 하나로 센다(계좌: 통장 사본 · 예금주 확인서 가운데 하나도 없으면 1) | 종류마다 서류 하나면 된다는 규칙(D65)이라 종류 단위로 센다 | 미확인 표에 빠진 서류 이름이 모두 보인다 |
| 판독 표의 주소 출처 행이 비교 상대 대리점의 등록 행이다 | 판독 값과 견주는 등록 값이 상대 대리점의 것이다 | 출처 설명 칸에 파일 · 행 · 대리점이 보인다 |
| 거부로 생긴 정황의 근거 표에 각 건의 지급일이 없다 | 근거 줄은 심사의 이름 · 귀속월 · 합산만 읽는다 | 근거를 누르면 그 심사(지급일 포함)가 열린다 |
