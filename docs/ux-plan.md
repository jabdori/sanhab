# UX 기획

화면별 배치. 근거는 `docs/service-plan.md`(S1~S8, U1~U7), `docs/research-ux.md`, `docs/user-scenarios.md`. 화면에 보이는 낱말은 `docs/design/copy.md`를 따른다. 전체 틀과 색은 확정(U8~U10). 전역 대화 칸은 논의 중.

## 전체 틀: 왼쪽은 고르는 곳, 가운데는 사실, 오른쪽은 판단

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ 합산      영업임원 ▾     2026-07-01     역할  날짜  초기화                     │ 띠
├────────┬───────────────┬──────────────────────────────┬───────────────────────┤
│ 작업   │ 목록          │ 사실                         │ 판단                  │
│ 대리점 │ (무엇을       │ (원본과 계산이 채운다)       │ (사람과 AI가 채운다)  │
│ 규정   │  볼지 고름)   │                              │                       │
└────────┴───────────────┴──────────────────────────────┴───────────────────────┘
   메뉴       목록               가운데                        오른쪽
```

| 자리 | 무엇이 놓이나 | 누가 채우나 |
|---|---|---|
| 왼쪽(메뉴, 목록) | 무엇을 볼지 고른다 | — |
| 가운데 | 대상의 사실: 구성, 금액, 관계 그림, 근거, 서류 원본, 규정 | 원본과 코드 계산 |
| 오른쪽 | 판단에 쓰는 것: 조치, 사유, 보고, 경위, 이력 | 사람과 AI |

- 오른쪽 칸은 모든 상세 화면에 같은 자리, 같은 순서로 있다: **조치 → 사유 → 보고 → 경위 → 이력**. 해당 없는 칸은 `없음`으로 남긴다(자리를 지운다).
- 가운데에는 AI가 쓴 글이 들어가지 않는다. AI가 쓴 것은 오른쪽의 "보고"에만 있다. 출처의 경계가 화면의 자리로도 보인다.
- 심사·정황·소명·지급은 메뉴에 없다. "작업" 목록에서 한 줄을 고르면 가운데와 오른쪽이 채워진다.
- 띠의 역할을 바꾸면 "작업" 목록이 그 역할의 것으로 바뀐다.
- 처음 들어올 때 접속 패스워드를 한 번 받는다(S2).

```
 담당 12   진행 5            [종류 ▾] [귀속월 ▾]
┌─┬──────┬──────────────────┬────────┬───────────┬────────┐
│☐│ 종류 │ 대상             │ 귀속월 │      합산 │ 표시   │
├─┼──────┼──────────────────┼────────┼───────────┼────────┤
│ │ 심사 │ 금강상사11 외 2  │ 2026-06│ 3,888,097 │ ⚑정황  │
│☐│ 심사 │ 대성상사1        │ 2026-06│   988,932 │        │
│ │ 추인 │ 금강상사11 외 2  │ 2026-01│ 4,870,186 │ ↻재검토│
└─┴──────┴──────────────────┴────────┴───────────┴────────┘

```

- 아무것도 고르지 않았을 때는 목록이 가운데까지 넓게 쓴다. 한 줄을 고르면 목록이 좁아지고 가운데와 오른쪽이 열린다.
- 선택 칸은 정황이 없고 전결 대상인 줄에만 있다(U4).
- "진행"에는 "담당" 열(지금 누구 차례인지)이 더해진다.
- 정황이 걸린 줄을 위로, 그다음은 합산이 큰 순.

- 가운데 맨 위 숫자 줄이 판단의 재료 전부다: 합산, 한도, 승인권자.
- 내가 승인권자가 아니면 "조치"에 버튼이 없고 `승인권자 영업임원`만 보인다.
- "관계"는 사람·주소·계좌를 점으로 그린다(U1). 대리점은 둥근 모양, 식별자는 각진 모양. 같은 내용이 "구성" 표의 "일치" 열에 글자로도 있다.
- 가운데의 "정황" 줄은 코드가 찾은 사실(종류, 대상, 가설 계산 결과)만 보여 준다. 그 정황에 대한 AI의 글은 오른쪽 "보고"에 있다.
- 승인된 뒤에는 "조치" 자리에 `승인 · 영업지원 · 2026-02-04 · 사유 없음(원본)`이 놓인다. 재검토이면 가운데에 당시와 현재를 나란히 둔다.

```
 금강상사11 외 2 · 2026-01                  [승인] ↻재검토
              당시              현재
 구성         단독              3곳
 합산         1,867,253         4,870,186
 승인권자     영업지원          영업임원
 인지일       미상
```

## 정황

```
 가운데                                          │ 오른쪽
 계좌 · 성일상사24                      [접수]   │ 조치
 근거 4   대리점 3   가설: 승인권자 변동 없음    │  요청   기각
                                                 │ 사유
 근거                                            │  [분류 ▾]  [메모      ]
  회수   2026-03-13  국민 412-27-556310          │ ─────────────────────
  회수   2026-04-13  국민 412-27-556310          │ 보고          AI [검토]
  계좌   금강상사11  국민 412-27-556310          │  사실
  계좌   대륙상사37  국민 412-27-556310          │   ① 회수 2건의 계좌가 … ↗1 ↗2
                                                 │   ② 같은 계좌를 계좌로 … ↗3 ↗4
 관계  (그림)                                    │  추정  …
                                                 │  미확인  예금주
 가설                                            │  의견 ▸
              현재        가설                   │  채택   불채택
  일치        대표자      대표자·계좌            │ ─────────────────────
  그룹        3곳         3곳                    │ 경위
  승인권자    영업임원    영업임원               │  07-01 원본  회수 2건
                                                 │ 이력
                                                 │  없음
```

- "사실"의 각 문장 끝 표시(↗)를 누르면 가운데 "근거" 표의 해당 줄이 강조된다. 값은 코드가 채운다.
- "미확인"은 접지 않는다. "의견"은 접혀 있다(U2). 임원 상신 대상인 정황에서는 내부 감시가 판단(조치)을 먼저 고른 뒤에 열린다.
- "보고"의 채택·불채택은 "조치"와 따로 남긴다.
- 다시 올라온 정황이면 "이력"에 `기각 · 내부 감시 · 2026-07-01 · 근거 부족`이 있고, 가운데 "근거"에서 새로 붙은 줄이 표시된다.

```
 │   (원본 이미지)      │  임차인 한라인상사34  …     일치 │ 보고             AI
 │     ▓▓▓▓▓▓ ← 강조    │  기간   2026.02.01~   —     —    │  정리
 │                      │                                  │   호실 302호 ↗

                                                           │  의견 ▸

```

- 가운데 왼쪽이 원본, 오른쪽이 값. 값의 줄과 원본의 위치가 서로 강조된다.
- 가운데의 "판독"은 글자 인식이 읽은 그대로다. AI가 다듬은 "정리" 값은 오른쪽 "보고"에 있고, 누르면 가운데의 판독 줄이 강조된다.
- 누락·불일치인 줄을 위로 올린다.
- 이 화면에서는 목록이 접힌다(서류에 폭을 준다).
- 영업지원이 보면 "조치"에 서류 올리기만 있다.

```
 가운데                                          │ 오른쪽
 한라인상사34   D-034                            │ 조치
 등록                     변경일      인지일  경로│  변경
  대표자 박준호      [원본] 2021-08-13 미상   원본│ 보고  없음
  주소   고양시 중앙로 128 [시연] 2026-02-01 2026-07-01 신고│ 경위
  계좌   신한 971-13-131178 [원본] 2021-08-13 미상 원본│  07-01 변경 주소
                                                 │ 이력
 관계  (그림 + 표)                               │
 지급  귀속월별 금액과 상태                      │
 정황 2   소명 1                                 │
```

- 날짜는 회사 쪽에서 본 둘이다: 변경일(사실이 바뀐 날), 인지일(회사가 안 날). "경로"는 어떻게 알았는지(신고, 회수, 소명, 원본).
- 값마다 출처 표지가 붙는다. 누르면 어디서 왔는지(원본 파일과 행)가 열린다.
- "변경"은 영업지원에게만 보인다. 항목, 새 값, 변경일을 받는다. 인지일은 시스템의 오늘로 찍힌다.

## 경위 (오른쪽 칸의 한 구획)

- 오른쪽에서는 시간순으로 위에서 아래로 한 줄씩 보인다(날짜, 종류, 대상).
- "경위"를 펼치면 가운데가 그림으로 바뀐다. 원인은 왼쪽, 결과는 오른쪽, 방향은 바뀌지 않는다.

```
 [변경 주소]──▶[재검토 2026-02]──▶[작업 추인]──▶[추인 영업임원]
 07-01 신고  ├─▶[재검토 2026-03]
             ├─▶[재심사 지급 2026-06]
             └─▶[정황 지연]──▶[보고 AI]
```

- 지금 보고 있는 대상의 줄기를 진하게 한다. 칸을 누르면 그 대상으로 간다. 결정 칸에는 사람과 사유가 붙는다.

## 열린 결정
- 오른쪽 끝의 전역 대화 칸(Q88~Q92)
