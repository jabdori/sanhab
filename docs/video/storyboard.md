# 시연 영상 스토리보드와 대본 (W07)

공식 기준: 음성 해설 필수, 장면마다 실제 작동 / 모의 처리를 말로 구분, 빨리 감은 구간은 화면에 표시, 5분 이내 권장, 1080p.
녹화는 배포본(https://app-x1sb.axhub.app)에서, 1920×1080 창, 녹화 전 `시연 → 초기화`. 장면마다 대본 음성의 길이에 화면 동작을 맞춘다.

## 화면 위에 얹는 것(hyperframes)
- **장면 제목**: 장면이 시작할 때 왼쪽 위에 2초 크게, 그 뒤 작게 남김. 예: `2 정상 · 전결과 대사`
- **자막**: 아래 가운데, 대본 문장 단위.
- **표지**: 오른쪽 위에 `실제 작동` / `모의 처리`. 모의 동작(모의 회신, 서류 올림, 발송)을 하는 동안만 `모의 처리`로 바뀐다. 빨리 감은 구간은 `×4 빨리 감기`.
- **누르는 동작**: agent-browser `record start --cursor`의 커서를 쓴다(누를 때 옅은 파란 원). 커서가 순간이동하지 않게 누르기 전에 `mouse move <x> <y> --duration 500~700 --human`으로 움직인 뒤 `mouse down/up`으로 누른다(`click`만 쓰면 커서가 그 자리에 바로 나타난다).

## 장면

### 1 소개 (약 30초)
역할: 접속 화면 → 영업지원
동작: 접속 패스워드 입력 → 역할 넷이 보이는 화면에서 1초 멈춤 → `영업지원` 누름 → 안내 `스킵` → 작업 목록
대본:
> W07, 관련 거래처와 판매장려금 지급입니다. 판매장려금은 대리점 한 곳에 한 달 이백만 원까지 영업지원이 전결하고, 넘으면 영업임원이 승인합니다. 문제는 이름이 다른 대리점이 같은 대표자, 주소, 계좌로 이어져 있을 때입니다. 규정은 이런 관련 거래처의 지급을 합쳐 한도를 보라고 합니다. 이 시스템은 영업지원, 영업임원, 내부 감시, 회계·자금 네 역할이 이 합산과 승인을 한 그래프 위에서 확인하고 처리하게 합니다.

### 2 정상 ① 전결과 대사 (약 40초) — 첫 실험 장면
역할: 영업지원 → 회계·자금
동작: 작업에서 `대성상사1` 줄 누름 → 요약의 합산·승인권자(영업지원)에 머묾 → `승인` → 역할을 `회계·자금`으로 → 작업의 `대성상사1` 지급 → `지급` → `시연`의 모의 회신(같은 금액·계좌, 성공) → 지급 머리 `완료`, 대사 `일치`
대본:
> 먼저 아무 문제 없는 건입니다. 대성상사1의 6월분 98만 8천 원은 관련 거래처가 없어 합산도 같고, 승인권자는 영업지원입니다. 영업지원이 승인하면 회계·자금에 지급 작업이 생깁니다. 회계가 지급하면 은행 회신을 기다리는 이체 상태가 됩니다. 은행 회신은 원본에 없어 모의로 넣습니다. 회신이 들어오면 코드가 승인 금액, 등록 계좌와 맞춰 보고 완료와 일치로 닫습니다. 계산, 승인, 대사는 실제 작동이고 은행 회신만 모의 처리입니다.

### 3 정상 ② 합산과 권한 (약 45초)
역할: 영업지원 → 영업임원
동작: 영업지원으로 `금강상사11 외 2` 열기 → 머리 단추에 승인이 없음 → 관계 영역(박상현 · 주소 · 계좌 선) → 역할 `영업임원` → 같은 심사 → 정황 영역 아래 AI 보고 카드로 내림 → `승인` → 사유 입력 → 확인
대본:
> 다음은 박상현 그룹입니다. 금강상사11, 성일상사24, 대륙상사37은 따로 보면 모두 한도 안이지만, 대표자와 주소, 대표자와 계좌가 이어져 한 그룹이 됩니다. 6월을 합치면 388만 8천 97원이라 영업지원 화면에는 승인 단추가 없습니다. 영업임원이 같은 심사를 열면 통장 공유 정황과, 그 근거를 정리한 AI 보고가 보입니다. AI는 기록을 가리킨 사실, 추정, 확인하지 못한 것을 나눠 쓰고, 합산과 승인권자는 만들지 못합니다. 판정은 사람이 하고, 정황이 걸린 건이라 승인 사유를 남깁니다.

### 4 조건 변경 · 주소 이전 신고 (약 70초)
역할: 내부 감시 → 영업지원 → 영업임원 → 회계·자금 → 내부 감시
동작: (준비, ×4 빨리 감기) 내부 감시가 `동명 · 박준호` 기각(사유), 영업지원이 `한라인상사34` 6월 승인 → 대리점 `한라인상사34` → 주소 변경: `고양시 중앙로 128`, 변경일 `2026-02-01` → 저장 → 영업임원 작업에 2·3월 추인과 6월 심사(2,255,709원) → 추인 하나 열어 재검토 표(당시 → 현재) → 회계·자금 작업의 지급 `재심사` → 내부 감시 작업의 정황 재접수(이전 기각 사유)와 `지연` → `경위` 탭
대본:
> 이번에는 조건이 바뀝니다. 내부 감시는 대표자 이름만 같던 한라인상사34와 금강상사41의 정황을 근거 부족으로 기각했고, 영업지원은 한라인상사34의 6월분을 전결했습니다. 그런데 7월 1일, 한라인상사34가 2월 1일부터 금강상사41과 같은 주소를 쓴다고 신고합니다. 변경일은 2월 1일, 회사가 안 날은 7월 1일로 따로 남습니다. 코드는 바뀐 주소 선에서 거슬러 영향을 찾습니다. 2월과 3월 승인은 합치면 한도를 넘어 재검토가 되고, 영업임원에게 추인 작업이 생깁니다. 과거 기록은 고치지 않고, 당시와 지금의 구성, 승인권자를 나란히 보입니다. 6월분은 합산 225만 5천 709원으로 영업임원 승인 대상이 되어, 회계·자금의 지급은 재심사로 멈춥니다. 기각했던 정황은 새 근거와 이전 기각 사유를 달고 내부 감시에 다시 올라오고, 다섯 달 늦은 신고는 지연 정황이 됩니다. 어느 작업에서든 경위를 열면 이 신고까지 거슬러 올라갑니다. 신고 입력만 시연자가 하고, 나머지는 모두 실제 작동입니다.

### 5 승인 거절 · 정보 부족 (약 70초)
역할: 영업임원 → 내부 감시 → 영업지원 → 내부 감시
동작: 영업임원 6월 심사 `보류`(사유) → 내부 감시 정황 `요청` → 소명의 AI 요청서 초안 → 영업지원 `발송` → `시연` 서류(호실 없는 임대차계약서) 올림 → (×4) 판독 → 미확인에 호실 → 내부 감시 `보완`(사유) → 보완 서류 올림 → (×4) 판독 → 비교: 205호 / 등록 101호 다름 → `인정`(사유) → 심사가 다시 별개로
대본:
> 영업임원은 바로 승인하지 않고 보류합니다. 사유가 남고, 지급은 계속 멈춰 있습니다. 내부 감시는 두 대리점에 소명을 요청하고, AI가 요청서 초안을 씁니다. 발송과 대리점의 서류 제출은 모의 처리입니다. 원본 주소에는 호실이 없어서 같은 건물인지까지만 알 수 있습니다. 올라온 임대차계약서는 글자 인식으로 읽고, AI가 임대 목적물의 호실을 찾습니다. 첫 서류에는 호실이 없어 미확인으로 남고, 내부 감시는 무엇이 빠졌는지 적어 보완을 요청합니다. 보완된 서류에서 호실이 다르다는 것을 코드가 등록 호실과 비교해 보입니다. 내부 감시가 인정하면 주소 선은 소명으로 제외되고, 두 대리점은 다시 별개가 되어 6월분은 각각 다시 심사됩니다. 글자 인식, AI 정리, 비교, 재계산은 실제 작동입니다.

### 6 필수 확장 · 다른 부서 영향 (약 30초)
동작: 장면 4의 추인 재검토 표 → 회계·자금 지급의 재심사 칸 → 정황의 근거(이전 기각 사유) 순으로 짧게 다시 보기
대본:
> 필수 확장은 정보가 정정됐을 때 무엇이 영향받고 왜 그렇게 됐는지를 그래프로 답하는 것입니다. 승인 당시를 굳혀 두는 버전 고정, 바뀐 선에서 거슬러 찾는 영향 추적, 처음 사건까지 닿는 경위가 장면 4에서 쓰였습니다. 그 결과 회계·자금의 지급이 멈추고, 내부 감시의 판단이 다시 열리고, 영업임원의 추인이 생겼습니다.

### 7 추가 확장 (약 30초)
역할: 영업임원
동작: 박상현 그룹 1~5월 추인 작업 → 규정 → `모의`에 1,500,000 → 달라지는 심사 수 → 대화 칸에 질문 하나(답이 오는 동안 ×4)
대본:
> 원본에서 박상현 그룹의 1월부터 5월 15건은 모두 전결로 나갔습니다. 이 시스템에서는 다섯 달 모두 영업임원 대상이고, 그 금액 2천 2백 23만 8천 349원은 손실이 아니라 승인권자가 달랐어야 하는 금액입니다. 규정 화면에서는 한도를 바꿔 승인권자가 달라지는 심사를 모의로 보고, 대화에서는 지금 연 기록에 대해 AI에게 물을 수 있습니다. 감사합니다.

## 만드는 순서(승인 뒤)
1. 대본 → OpenAI TTS(장면마다 파일 하나) → 길이 측정.
2. 배포본을 깨워 장면 2 하나만 녹화해 실험: agent-browser 녹화(누르는 동작이 보이게) → hyperframes로 제목 · 자막 · 표지 → ffmpeg로 음성과 합침. 결과를 보여 드리고 확인받음.
3. 나머지 장면 녹화 → 이어 붙이기 → 앱 초기화 → 재우기.
