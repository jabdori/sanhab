# 검사 절차 (디자인 하네스)

화면을 만든 쪽이 스스로 통과시키지 않는다. 만든 쪽과 다른 별도의 에이전트가 agent-browser로 화면을 실제로 띄워 눈으로 검수한다.

## 언제
- 화면 하나(또는 시나리오 하나)가 끝날 때마다.
- 배포 전에 시나리오 전체를 한 번.

## 검수하는 쪽에 주는 것
- 이 폴더의 문서: `tokens.md`, `components.md`, `copy.md`, `sources.md`
- 본보기 화면의 그림(심사: 영업지원 대성상사1, 영업임원 금강상사11 외 2) — 일관성을 견줄 기준
- `docs/ux-plan.md`(배치), `docs/user-scenarios.md`(따라갈 순서)
- 로컬 주소와 접속 패스워드, 검수할 화면·시나리오의 이름
- 만든 쪽의 설명이나 "잘 됐다"는 판단은 주지 않는다. 문서와 화면만 준다.

## 검수하는 방법
1. agent-browser로 로컬 주소를 1440 × 900으로 연다. 창을 띄우지 않는다(headless, `--headed` 금지). Playwright MCP 같은 다른 브라우저 도구는 쓰지 않는다. 접속 패스워드를 넣는다.
2. 띠에서 역할을 바꿔 가며 시나리오의 순서를 그대로 따라간다. 조치는 실제로 누른다.
3. 단계마다 화면을 찍어 저장한다(파일 이름: `시나리오번호-단계-역할.png`).
4. 아래 항목을 화면과 대조한다. 코드가 아니라 화면에 보이는 것으로 판단한다.
5. 끝나면 초기화해서 다음 검수가 같은 상태에서 시작하게 한다.

## 항목
**문구 (`copy.md`)**
- 이름표·탭·표지·버튼에 조사, 어미, 문장 부호가 있는가
- 화면 표기 표에 없는 낱말이 있는가
- 같은 개념이 화면마다 다른 낱말로 적혀 있는가
- 안내 문장이 값이나 표로 바뀔 수 있는가

**자리 (`ux-plan.md`)**
- 가운데에 AI가 쓴 글이 있는가(있으면 안 된다)
- 오른쪽 칸의 순서가 조치 → 사유 → 보고 → 경위 → 이력인가, 해당 없는 칸이 한 줄 "없음"으로 접혀 남아 있는가
- 대화 칸에 "임시"가 보이는가, 보고와 모양이 구분되는가
- 1280 폭에서 깨지는가

**모양 (`tokens.md`, `components.md`)**
- 상태 표지의 색이 다섯 가지 밖인가, 색만으로 구분되는 것이 있는가
- 금액이 오른쪽 정렬·고정폭인가, 날짜 형식이 한 가지인가
- 덧표시와 출처 표지에 색이 들어갔는가
- 목록에 없는 부품이 쓰였는가

**시각 (`tokens.md`, `components.md`) — 화면을 찍은 그림으로 판단한다**
- 위계: 눈을 가늘게 떠도 화면 제목 → 숫자 줄 → 영역 제목 → 본문 순으로 읽히는가. 영역 제목이 본문보다 작거나 옅은가(그러면 안 된다)
- 버튼 등급: 조치 묶음마다 주 버튼(primary)이 정확히 하나인가(`grade.ts`). 채택·불채택은 같은 무게인가. destructive가 초기화 밖에 쓰였는가
- 영역 구분: 가운데(흰색 사실)와 오른쪽(회색 판단)이 바탕으로 갈리는가. 영역이 간격으로 나뉘고 카드로 감싸지 않았는가. 머리(제목·숫자 줄)가 스크롤해도 남는가
- 일관성: 같은 종류의 것(표, 이름 열, 출처 열, 이력 한 줄, 빈 영역, 상태 표지)이 심사 화면과 같은 모양인가. 옛 이름(`text-text-sub`, `button`)이나 Base UI가 남았는가
- 빈 영역: 내용 없는 영역이 한 줄(`경위 없음`)로 접혔는가, 큰 빈 칸이 같은 무게로 자리를 차지하지 않는가
- 출처: 원본 값에 표지가 붙지 않았는가(조용한 행 번호만). 원본이 아닌 값마다 표지가 있고, 머물면 한 줄, 누르면 설명 칸이 열리는가. 가정의 설명 칸에 결정 번호·본문·쓰임이 있는가
- 시연 분리: 제품 화면에 날짜 넘기기·초기화·시연 서류·모의 회신의 단추가 없고 `시연` 서랍에만 있는가
- astryx 기본 영어 문구(`Cancel`, `Required`, `Select...`, `No results`)가 보이는가

**동작 (`user-scenarios.md`)**
- 시나리오의 각 단계가 적힌 대로 일어나는가(숫자까지: 합산, 승인권자, 재검토가 되는 달)
- 권한이 없는 역할에 조치 버튼이 보이는가
- 사유가 필수인 결정이 사유 없이 눌리는가
- 근거 연결을 누르면 가운데의 해당 줄이 강조되는가
- 출처 표지를 누르면 어디서 왔는지가 열리는가, 원본의 행 번호를 누르면 원본 행이 열리는가

## 결과
검수한 쪽은 아래 형식으로만 돌려준다.

| 시나리오·단계 | 항목 | 본 것 | 기대한 것 | 무게 | 화면 파일 |
|---|---|---|---|---|---|

- 무게: **막힘**(시나리오가 진행되지 않거나 숫자·권한이 틀림) / **어김**(문서의 규칙과 다름) / **참고**(규칙에는 없지만 어색함).
- 막힘과 어김이 하나도 없어야 통과다. 참고는 만든 쪽이 판단한다.
- 고친 뒤에는 같은 시나리오를 다시 검수한다. 같은 화면에서 세 번째 검수까지 통과하지 못하면 멈추고 유저에게 알린다.
- 문서의 규칙이 틀렸다고 보이면 화면을 문서에 맞추지 말고 그 점을 결과에 적는다. 규칙을 고칠지는 유저가 정한다.
