# 부품 목록 (디자인 하네스)

화면은 아래 부품만으로 만든다. 우리 부품(`app/web/src/ui/`)이 있으면 그것을, 없으면 astryx 부품을 바로 쓴다. 새 부품이 필요하면 이 표에 먼저 더한다.
화면의 낱말은 모두 `app/web/src/labels.ts`에 있다(`copy.md`). 부품 안에 글자를 직접 적지 않는다. astryx 부품의 기본 영어 문구(`Cancel`, `Required`, `Select...`)가 화면에 나오지 않게 해당 props에 낱말을 준다.
**본보기는 심사 화면**(`tickets/04-심사`, 그리고 심사에 끼는 05·06·09·10·11·12·16의 조각)이다. 화면을 옮길 때 이것과 나란히 놓고 맞춘다.

## 버튼 등급
- **조치 묶음마다 주 버튼(primary)은 하나**: 흐름을 앞으로 보내는 조치(승인, 추인, 종결, 요청, 인정, 발송, 지급, 회신, 재상신, 변경, 접수). 목록은 `ui/grade.ts`, 버튼은 `<Button variant={grade(kind)} …>`.
- 나머지 조치는 secondary(보류, 반려, 거부, 이견, 기각, 불인정, 보완 …).
- **destructive는 기록을 지우는 시연 조작(초기화)에만.** 반려·불인정·거부·기각은 사유와 함께 남는 결정이고 되돌리는 길(재상신·보완·이견·재접수)이 있어 붉게 칠하지 않는다. 붉은 버튼이 판단을 한쪽으로 미는 것도 막는다.
- **예외: 보고의 채택·불채택은 둘 다 secondary**(같은 무게, `docs/research-ux.md`). AI의 의견을 받아들이는 쪽으로 기울이지 않는다.
- 권한이 없으면 버튼 대신 `승인권자 영업임원`(이름표는 보조, 값은 굵게). 비활성 버튼을 늘어놓지 않는다.
- 확인 창의 실행 버튼은 여는 버튼과 같은 등급, 취소는 secondary.
- 크기는 기본(md) 하나. 띠의 `시연`만 sm.
- 모양: primary는 검정 채움, secondary는 흰 바탕 + 테두리(`theme.ts`), 누를 수 없으면 반투명. 버튼 모양을 className으로 덮지 않는다.

## 출처 표지
근거: `01_참가자_배포용/A05.html` §6(원본 사실·추가 가정·합성 관측값·계산 결과를 구분 표시, 추가 행에 식별자·적용 시점·원본 연결·생성 이유, 모의 회신은 가상 입력).

| 출처 | 화면 | 설명 칸 |
|---|---|---|
| 원본 | **표지 없음.** 출처 열에 조용한 행 번호(`55행`, 보조 색) | 원본 파일의 그 행: 경로·행, 머리글과 값, 해시 |
| 계산 | Token `계산` | 이름표와 값으로 쓴 계산식(`합산  귀속월 지급의 합, 반려 제외`) |
| 가정 | Token `가정` | MetadataList: 번호(D51) · 내용(스펙의 그 줄) · 적용 시점(기준일 `2026-07-01 ~`) · 위치(문서와 행) · 이유(결정 제목 + 본문, 160자를 넘으면 접힘, 글머리는 목록으로 — Markdown) · 쓰임 |
| 합성 | Token `합성` | 가정과 같다(D58 시연 호실) |
| AI | Token `AI` | 실행 기록(모델 · 날짜 · 조회) |
| 모의 | Token `모의` | **시연 서랍에서 만든 값에만**(모의 회신, 시연 서류, 넘긴 날짜): 종류 · 대상 · 넣은 값 · 누가 언제 · 이유(시연) |

- 부품: `<Source kind={…} file row tip of rows side>{설명}</Source>`. 계산의 설명은 `rows`(이름표와 값의 줄, MetadataList로 그린다). `dl`·`grid`를 손으로 짜지 않는다. 줄로 쓸 수 없는 글(조항 원문)만 children. 머물거나 초점을 주면 **한 줄**(`가정 D51 · 근접`), 누르면 **설명 칸**.
- 가정·합성의 내용은 `GET /api/rules`의 `assumes`·`synths`(결정 번호·제목·스펙의 줄·행·본문 `body`·쓰임) 한 곳에서 온다. 화면에는 **값 → 결정 번호** 대응만 둔다(`ui/Source.tsx`의 `DECISION`: 기한 D32, 지연 D30, 근접 D51, 서류 D17, 호실 D58). 새 가정을 쓰면 거기에 한 줄을 더하고 `<Source kind={L.가정} of={L.낱말} />`.
- 서버의 출처 `시연`은 사람이 앱에서 한 조치(변경·승인·요청)와 시연 서랍의 조작을 가르지 못한다. 그래서 화면이 가른다: **제품 안의 조치로 생긴 값은 표지가 없다**(누가 언제는 이력에), 시연 서랍에서 온 값(08 회신, 19 시연 서류)만 `kind={값.source}`로 넘겨 `모의`로 보인다. 시연으로 넣은 값(D58의 호실)은 `kind={L.합성} of={L.호실}`. 서버는 바꾸지 않는다.
- 원본의 조용한 글자는 언제나 행 번호다: csv는 `row`(`7행`), 문서의 여러 행은 `place`(`41–45행`). 표의 출처 열이나 숫자 줄의 값 옆에 둔다(값의 칸 안에 섞지 않는다).
- 표 전체가 같은 출처면(규정의 가정 목록) 줄마다 표지를 달지 않고 `quiet place={번호}`로 번호가 설명 칸을 연다. 한 결정에 줄이 여럿이면 `line`(스펙의 행)으로 그 줄을 고른다.
- 설명 칸의 글(조항 원문 등 마크다운)은 children에 문자열로 주면 그려진다(Markdown). 가리킬 값이 없으면 표지를 달지 않는다(기한 없음 옆의 가정 등).
- 표지의 툴팁은 아래로 뜬다(위의 이름표를 덮지 않게).
- 앱에서 사람이 내린 결정(승인·반려 …)은 제품의 동작이라 표지를 달지 않는다. 누가 언제는 이력에 있다.
- 표의 출처 열, 숫자 줄의 끝, 영역 제목 옆(`Region aside`)에 둔다. 값 안에 섞지 않는다.

## 시연 서랍
- 띠의 `시연`(secondary sm)을 누르면 오른쪽에서 서랍이 겹쳐 뜬다(Drawer, 막지 않음 — 뒤 화면이 그대로 움직인다).
- 담는 것: 날짜 넘기기, 초기화(destructive, 확인 창), slot `demo`의 조각 — 소명의 시연 서류(19), 지급의 모의 회신(08). `kind`가 있는 조각은 그 대상을 열었을 때만 보인다.
- 제품 화면에는 이 조작의 단추를 두지 않는다. 그 조작으로 생긴 값에는 출처 표지 `모의`만 남는다.
- 규칙 모의(23, 규정 화면)는 제품의 기능이라 서랍에 넣지 않는다.

## 빈 영역
- 영역(`Region`)의 몸통이 `없음`(`Empty`)뿐이거나 비면 **제목과 없음이 한 줄로 접힌다**(제목은 보조 색 본문 크기, 위아래 여백 8). 자리와 순서는 지키되, 내용이 있는 영역과 같은 무게로 자리를 차지하지 않는다(theme.css `[data-region]`).
- 그래서 조각은 내용이 없으면 `<Empty />`를 돌려주거나 아무것도 그리지 않는다. 빈 영역에 그림·안내 문장을 두지 않는다.
- 숫자가 없는 출처 표지(관계가 없을 때의 계산 등)는 그리지 않는다.

## 판단 칸·보고·대화
- 판단 칸: 조치 → 사유 → 보고 → 경위 → 이력. 순서 고정.
- 이력 한 줄(`ui/Line`, 결정은 `04`의 `Line`이 감싼다): 결정(굵게) · 사람 · 날짜 · 사유의 분류(보조 색). 메모는 그 아래 줄. 원본의 과거 결정은 `사유 없음(원본)`.
- 결정이 내려진 대상의 조치 칸은 그 결정 한 줄이다(ux-plan: `승인 · 영업지원 · …`). 소명의 결과(인정·불인정·보완)가 나면 조치 칸은 발송한 요청서가 아니라 그 결정이다.
- 경위: 목록은 사슬의 순서(원인 → 결과). 그림을 펼치면 머리는 남고 몸통만 그림이 되며 목록이 접힌다(폭). 칸은 종류·날짜 / 대상 / 사람·사유, 선은 열 사이에서 꺾인다.
- 보고: 사실 / 추정 / 미확인 / 의견·반론. 머리에 `AI` 표지와 상태 표지. "사실"의 끝에 근거 연결(`↗`, 누르면 가운데의 그 줄이 강조). "미확인"은 접지 않는다. "의견"은 접힘. 확신을 숫자로 적지 않는다.
- 대화: 머리에 `대화`와 `임시`. AI의 답 아래에 조회한 기록. 조치 카드는 대상·조치·사유를 보이고 `실행`(primary)으로 실행. 권한 없는 조치는 그리지 않는다.

## 화면 하나를 옮기는 절차
1. 심사 화면(`tickets/04-심사/index.tsx`)과 이 문서를 연다. 옮길 티켓의 `index.tsx`에서 `ui/styles`·`@base-ui`·옛 이름(`text-text-sub`, `text-figure`, `h-head` …)을 찾는다.
2. 제목 줄과 숫자 줄을 한 조각으로 모아 `slot: 'head'`로 옮긴다(`Title` + `Pill`·`Mark` + `Figures` + 출처 표지).
3. 가운데의 덩어리마다 `<Region title={L.…} aside={출처 표지}>`로 감싼다. `<h2 className={label}>`, `mb-4`, `section` 껍데기를 지운다.
4. 표는 `ui/Table`: 이름 열은 `Text weight="medium"`(또는 다른 대상으로 가면 `Link`), 목록이면 `onRow`, 출처는 마지막 열의 `Source`.
5. 버튼은 `Button variant={grade(kind)}`, 확인이 필요하면 `Confirm`. 다른 입력은 astryx(Selector, TextInput, NumberInput, RadioList, CheckboxInput, ToggleButton, Collapsible)로 바꾸고 Base UI를 지운다.
6. 출처: 원본은 `file`·`row`만(표지 없이 행 번호), 계산은 `tip`과 이름표·값의 설명, 가정·합성은 `of={L.낱말}`(없으면 `DECISION`에 한 줄). 시연 조작의 단추가 있으면 `slot: 'demo'` 조각으로 뺀다.
7. 내용이 없으면 `<Empty />`(영역이 한 줄로 접힌다). 영어 기본 문구가 보이지 않게 props에 낱말을 준다.
8. `npm run build` → 1440·1280에서 심사 화면 그림과 나란히 찍어 `review.md`의 시각 항목으로 견준다.

## 마지막 다듬기에서 정한 것
- 원본 레코드 하나가 화면의 대상이면(지급, 대리점, 조항) 그 행 번호는 **제목 줄**의 조용한 글자다(`대성상사1 2026-06 7행`, `41–45행`). 숫자 줄의 값 옆에는 두지 않는다.
- 표의 열 출처는 표 안에 `출처` 줄을 두지 않고 영역 제목 옆(`Region aside`)에 둔다(대사: `모의`·`계산`).
- 좁은 목록(360)의 이름 열은 `clip` — 줄임표로 줄고(머물면 전체), 금액은 늘 보인다. 목록의 이름 Link는 머문 줄에서만 밑줄(theme.css `.rows-open`).
- 사유 칸은 그 대상의 조치(요청·기각 …)만 받는다. 조치가 없으면 접힌다. 보고의 채택·불채택 사유는 보고 칸 안, 버튼 바로 위에서 고른다.
- 날짜 입력은 `DateInput presentation="native"`(띄운 달력이 버튼을 가리지 않는다). 오늘 뒤는 고를 수 없다(`max`).
- 대화의 조회한 기록은 화면이 있는 기록이면 이동 링크(서버의 `data-reads.go`), 없으면 글자.
- 설명 칸 안의 마크다운 제목은 h5 등급부터(영역 제목보다 작게). 스펙 줄의 글머리(`- `, `4. `)와 `가정 —`는 떼고 내용만.
- 서버의 출처 `시연`(사람이 제품에서 한 조치로 생긴 값)에 표지가 없는 것은 `ui/Source.tsx` 한 곳이 정한다(`kind`가 `시연`이면 그리지 않는다). `모의`는 시연 서랍에서 만든 값에만 부르는 쪽이 `kind={L.모의}`로 준다(지금은 모의 회신).
- AI(보고·대화)가 읽는 도구 결과에서 출처 `시연`은 `화면 입력`으로 바뀌어 건너가고, 지시문이 그 뜻(사람이 화면에서 한 조치)을 적는다(t17 `human`·`SOURCE`). DB와 화면의 값은 그대로다.
- 시연 서랍은 띠 아래에서 열린다(theme.css `.demo-drawer`). 초기화 확인 창은 지워지는 기록(`대상`)과 날짜(`이전 → 2026-07-01`)를 보인다.
- 작업 목록의 지급 `상태`는 그 지급의 상태(서버 `pay`)이고 작업의 상태가 아니다.
